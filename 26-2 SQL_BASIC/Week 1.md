## 1.1 BigQuery 기초 지식
## 01.

**bigquery 기본 지식**

bihquery란?

데이터 저장 형태  
데이터베이스 테이블 등에 저장  
Datebase : 데이터 저장소 / Talbe : 데이터 저장된 공간

**OLTP** (Online Transaction Processing)
- 거래를 하기 위해 사용되는 데이터 베이스 : 데이터가 무결하다 (주문을 완료하거나 하지 않거나)
- 데이터의 추가와 변경이 많이 발생
- 분석용이 아니므로 쿼리 속도가 느릴 수 있음

**SQL** : 데이터베이스에서 데이터를 가지고 올 때 사용하는 언어
데이터 관리를 위한 특수 목적의 프로그램

### 테이블에 저장된 데이터의 형태
-> 테이블에 저장된 형태는 엑셀, 스프레드 시트와 유사

1. 로우(row) : 행, 가로로 한 줄을 의미
   - 하나의 row가 하나의 고유한 데이터
   - raw 데이터와 헷갈림 주의
3. 컬럼(Column) : 열, 세로로 연상
   - 각 데이터의 특정 속성 값
   - 거래의 구매 시간, 거래의 구매자

웨어하우스(DW)의 등장
1. 등장 배경 : OLTP의 속도, 기능 부족의 문제로 OLAP 등
2. OLAP(Online Analytical Processing)란? : 분석을 위한 기능이 제공되는 서비스
3. 데이터 웨어하우스 : 데이터를 한 곳에 모아서 저장

BigQuery가 구글의 OLAP+웨하우스임
장점
1. 쉬운 난이도 : SQL 사용하여 쉽게 데이터 추출
2. 빠른 속도
3. 앱 웹에서 데이터를 쉽게 추출할 수 있음
4. DW 사용하기 위해 별도의 서버 띄울 필요 없음

사용하는 이유
1. 앱이나 웹에서 firebase, 구글 애널리틱스4 활용할 경우
2. 운영을 적은 비용으로

빅쿼리 비용 (알면좋음) /US비용
-> 쿼리 비용 / 저장 비용 두 가지

1. 쿼리 비용
   - On-demand 요금제 : 쿼리에서 처리된 용량만큼 부과 1TB 6.25 (일반적으로 사용)
   - Capacity 요금제 : slot 단위로 요금 부과 1슬롯 시간당 부과
