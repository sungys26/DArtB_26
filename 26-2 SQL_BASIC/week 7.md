## WEEK 2
## 02. FROM , WHERE, SELECT
```
✅ 어떤 테이블에서 어떤 조건으로 어떤 컬럼을 고를지 처리하는 기본 쿼리 문법
✅ 모든 쿼리에 있어 필수적으로 필요한 베이직 문법
```
**💡문법 정의**  
- `FROM` : 어떤 테이블에서 데이터를 가져올 것인지
- `WHERE` : 어떤 조건으로 컬럼을 거를 것인지
- `SELECT` : 어떤 컬럼을 고를 것인지
  - **SQL 실행 순서** : FROM → WHERE → SELECT
 
**활용한 코드**
```SQL
SELECT
  Col1 AS new_name,
  Col2
FROM Dataset.Table AS TB
WHERE Col1 = 1
```
- 테이블은 AS 문법을 통해 별칭을 붙여 편리하게 사용할 수 있다
- SELECT * EXCEPT (컬럼) 을 사용하면 지정한 컬럼을 제외한 나머지 컬럼을 출력할 수 있다

**📌헷갈리는 부분 정리** 
```
- 조건에 쓰는 컬럼과 출력할 컬럼은 따로 생각, 무엇을 WHERE에 넣을지, SELECT에 넣을지 고민해야 한다
- WHERE에서 사용하는 컬럼은 SELECT에 나열하지 않아도 된다
- WHERE은 ORDER BY 이전에 온다
```


## WEEK 3
### 03. GROUP BY, HAVING
```
✅ 분석에 필요한 데이터 요약을 위한 묶기 문법
✅ 조건에 사용하는 WHERE과의 차이 파악
```
**문법 정의**
- `GROUP BY` : 특정한 컬럼 값이 같은 행끼리 묶어 그룹으로 집계
- `HAVING` : 묶은 뒤 집계 결과에 조건을 거는 문법

**활용한 코드**
```SQL
SELECT ANIMAL_TYPE, COUNT(*) AS count
FROM ANIMAL_INS
GROUP BY ANIMAL_TYPE
ORDER BY ANIMAL_TYPE;
```
- 집계 없이 SELECT에 쓴 컬럼은 GROUP BY에 포함해야 한다
- WHERE은 집계 전의 행을, HAVING은 집계 후의 그룹을 거르는 문법이다
- 상단의 코드에 HAVING 문법이 사용되지는 않았지만 만약 사요하게 된다면 집계 함수는 HAVING에서만 쓸 수 있다

---

### 04. 집계 함수 - COUNT, SUM, AVG, MAX, MIN
```
✅ 여러 행을 하나의 숫자로 요약하는 함수로 지표를 만들 때 가장 많이 사용
```
**문법 정의**
- `COUNT` : 개수 / `SUM` : 합계 / `AVG` : 평균 / `MAX` : 최댓값 / `MIN` : 최솟값

**활용한 코드**
```SQL
SELECT MAX(PRICE) AS MAX_PRICE
FROM PRODUCT;
```
- 전체 행을 세고 싶을 때는 COUNT(*)를 활용, 나머지는 NULL을 제외하고 계산한다
- MAX는 숫자뿐 아니라 날짜와 시간 컬럼에도 사용 가능하다

### 06. CAST, SAFE_CAST
```
✅ 데이터 타입을 변환하여 계산이나 비교에서 발생하는 에러를 방지
✅ 보이는 값과 저장된 타입이 다르면 에러 발생하므로 데이터 타입 확인 필수
```
**문법 정의**
- `CAST` : 데이터 타입을 변환하는 함수
- `SAFE_CAST` : 데이터 타입 변환에 실패할 경우 에러 대신 NULL을 반환
  - 사용 예시 상황 : 부울 값이 문자열 ‘true’/’false'로 저장된 경우에 변환이 필요

**대표적 데이터 타입**
> 숫자, 문자, 시간, 날짜, 부울(True/False)

**활용 예시 코드**
```SQL
SELECT
  CAST(1 AS STRING),
  SAFE_CAST("다트비" AS INT64)  -- 변환 실패 시 NULL
```


## WEEK 5
### 07. CASE WHEN, IF
```
✅ 조건에 따라 값을 나누거나 카테고리를 합치는 전처리에 사용
```
**문법 정의**
- `CASE WHEN` : 조건에 따라 다른 값을 출력, 조건이 여러 개일 때 사용
- `IF` : 단일 조건일 때 사용

**헷갈리는 부분 정리**
```
- 여러 조건에 해당하면 앞서 작성한 조건이 우선된다
- 조건에 쉼표를 붙이지 않도록 주의한다
- ELSE와 END AS를 붙이는 것 잊지 말고, 컬럼명 역시 빠트리지 말아야 한다
```

**활용한 코드**
```SQL
SELECT
  BOARD_ID, WRITER_ID, TITLE, PRICE,
  CASE WHEN STATUS = 'SALE' THEN '판매중'
       WHEN STATUS = 'RESERVED' THEN '예약중'
       WHEN STATUS = 'DONE' THEN '거래완료'
  END AS STATUS
FROM USED_GOODS_BOARD
WHERE DATE_FORMAT(CREATED_DATE, '%Y-%m-%d') = '2022-10-05'
ORDER BY BOARD_ID DESC;
```

### 08. 날짜, 시간 함수 - EXTRACT, DATETIME_DIFF, FORMAT_DATETIME, PARSE_DATETIME

```
✅ 날짜와 시간을 표현하는 데 있어서 활용하는 함수
✅ 기간 계산과 연도, 월별 집계
```
**문법 정의**
- `EXTRACT` : 날짜, 시간 컬럼에서 연, 월, 일과 같이 일부만 추출
- `DATETIME_DIFF` : 두 시점의 차이를 계산
- `FORMAT_DATETIME` : DATETIME을 문자열로 변환
- `PARSE_DATETIME` : 문자열을 DATETIME으로 변환

**추가적으로 학습한 내용 정리**
- DATE는 날짜만, DATETIME은 타임존 없는 날짜와 시간
- TIMESTAMP는 UTC 기준의 시점이라 한국 시간과 9시간 차이

❗프로그래머스와 MySQL에서 사용하는 형태가 달랐음
```
-- MySQL (프로그래머스)
AVG(DATEDIFF(END_DATE, START_DATE) + 1)

-- BigQuery 대응
AVG(DATETIME_DIFF(END_DATE, START_DATE, DAY) + 1)
```


## WEEK 6
### 09. JOIN - INNER, LEFT 등
```
✅ 여러 테이블을 하나로 연결하는 작업
✅ 통합된 하나의 테이블에서 원하는 조건의 행들을 추출 가능
```
**문법 정의**
- `JOIN` : 공통된 컬럼이 존재하는 다른 테이블 두 개를 하나의 테이블로 연결
- `INNER JOIN` : 두 테이블의 공통된 요소만 연결
- `LEFT/RIGHT JOIN` : 왼쪽/오른쪽 테이블이 기준이 되어 연결되는 함수
  - 기준이 되는 테이블의 반대 방향에 짝이 될 것이 없으면 NULL 처리가 된다

**집합의 관점으로 이해하는 JOIN의 종류**
<img width="1282" height="508" alt="image" src="https://github.com/user-attachments/assets/9ca372d2-d011-4000-86a2-ffa496a0ec33" />

**작성 방법 및 주의사항**  
- 테이블 확인 → 기준 테이블 정의 → JOIN KEY 찾기 → 결과 예상 → 쿼리 작성
- 문법은 항상 FROM, LEFT/INNER JOIN, ON 순서
- 

**활용한 코드**
```SQL
SELECT O.ANIMAL_ID, O.NAME
FROM ANIMAL_OUTS AS O
LEFT JOIN ANIMAL_INS AS I
ON O.ANIMAL_ID = I.ANIMAL_ID
WHERE I.ANIMAL_ID IS NULL
ORDER BY O.ANIMAL_ID
```
- **📌헷갈렸던 부분** : 반드시 `ON` 사용하기 (CROSS만 ON이 필요하지 않다)
